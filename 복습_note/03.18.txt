02 SQL 분석도구

1. 오라클 예상 실행 계획 
  explain plan - 실행 계획을 확인하는 방법 
  dbms_xplan.display - plan table에서 저장된 정보를 읽어 분석하기 쉬운형태로 포맷팅하는 함수

2. showplan_text - 서버에서 예상 실행계획을 출력하는 방법 set showplan_text on 실행 후 sql실행

3. dbms_xplan.DISPLAY (예상 실행 계획) 에서 알 수 있는 정보
TYPICAL(기본값) -> plan hash, value, operation, object Name, 
                   예상 cardinality, 예상 cost, 예상 CPU time
예상 sort 정보 -> 실행계획에서 알 수 없다.
                  sort 정보는 dbms_xplan.DISPLAY_CURSOR (실행정보) 에서 확인 할 수 있음


4. 오라클 AUTOTRACE에서 확인 할 수 있는 정보.
   
autotrace와 explainplan의 차이점
explainplan : 실제 sql을 실행하지 않고 예상계획만 제시
autotrace : sql을 실제로 실행하고 실행계획 + 성능 통계 제공

autotrace에서 실제 확인 할 수 있는 정보
예상 실행계획 + 실제 디스크에서 읽은 블록 수 + 실제 기록한 redo크기

** 실제 사용한 cpu의 time은 autotrace에서 알 수 있는 정보가 아니다.

set autotrace traceonly; -> 쿼리결과는 출력하지 않고 실제 실행계획과 통계만 확인

5. autotrace 실행 옵션 
sql을 실제로 수행하지 않고 예상 실행계획만 출력하고자 할때
set autotrace on traceonly explain
set autotrace on traceonly exp

6. 오라클에서 sql 트레이스를 확인 할 때 명령어
alter session set sql_trace - true

7. 오라클에서 트레이스 파일을 분석 후 리포트 파일을 생성해주는 명령어

TKProf 유틸리티
  sqltrace파일 (.trc)을 읽고, 분석한 결과를 리포트 파일로 생성하는 오라클 성능분석 유틸리티
  dbms_xplan.display_cursor와의 차이점
  cpu, disk, io, fetch회수등 상세한 정보 제공 <-> 일부 성능 통계 제공
  실행 후 trace파일이 필요하다.

tkprof : 실행 후 분석
         실행된 sql의 모든 성능 정보가 trace(.trc) 파일에 저장이 되어짐
         sqltract -> tkprof유틸리티 사용 -> 리포트 제공

dbms_xplan.display_cursor : 실제 실행된 sql의 실행 계획을 확인
          오라클이 실제 실행된 sql 실행계획을 확인가능
          trace파일 없이 실제 실행된 sql의 실행계획을 바로 확인
          explain plan 보다 정확한 실제 실행 계획을 조회가능

sqltrace > dbms_xplan.display_cursor > dbms_xplan.display 순서대로 정확한 통계를 확인 할 수 있음.



구조적 데이터
  행과 열 형태로 잘 정돈되어 있으며 스키마에 따라 저장되어진다. 
  예 : db테이블 , csv파일등 형식데이터
  장점 : 쿼리 분석이 빠르고 효육적이다.
  단점 : 유연성이 떨어진다. (새로운 속성을 추가하려면 스키마 변경이 어려움)

비구조적 데이터
  특징 : 텍스트, 이미지 , 오디오, 동영상등 고정된 스키마 없이 다양한 형태를 가진다.
  장점 : 형태가 자유로워서 어떤 데이터든 자유롭개 저장가능 (flexibility 가 높음)
  단점 : 검색이나 구조화된 분석이 어려우며, 용량이 크다.

반 구조적 데이터 (semi structed data)
  특정 부분은 구조화가 되어 있지만 완전한 테이블 구조가 아닌 데이터
  json, xml iot센서 로그
  장점 : 정형/비정형 데이터의 중간 형태로, 어느정도의 검색/정리가 가능하며 유연성도 가진다.

flexivility vs efficiency
  flexibility : 새로운 속성을 추가 하거나 데이터 구조를 변경하는데 얼마나 유연한지
  efficiency : 저장 검색 분석 시 필요한 자원이나 속도 측면에서 얼마나 효율적인지
  구조적인 정도가 높을수록 효율적이나 유연성은 떨어진다.
  비구조적인 정도가 높을수록 유연성은 높으나 검색 분석은 어려워진다.


객체와 속성
  객체(object) 
  하나의 샘플(인스턴스) : 사람 1명, 제품 1개, 이미지 1장

  속성(attribute) = 피쳐 (feature)
  객체가 가진 특성값
  사람이라면 : 나이 , 키 , 몸무게 , 직업

 
  속성(피쳐)의 유형
  nominal(명목형) : 이름이나 레이블로 구분되어진다.
  예 : 지역명, 우편번호, 학번
 
  binary (이진형)
  0/1, true/false 처럼 두 가지 상태만 존재
  대칭적 : 0/1 의 중요도가 동일한경우
  비대칭적 : 1양성 이 0음성 보다 중요하거나 관심대상인 경우
 
  양적(수치형) 속성 (quantitative/ numeric)
  interval scale( 구간척도 )
  구간(간격)은 있지만 절댓값 0 이라는 개념이 없다.
  ratio scale( 비율척도)

분류(classification)
  사전에 정의된 레이블(클래스)을 예측하는 문제
  예시 : 이사람이 암양성인지 음성인지, 신문 카테고리, 거래내역 정상인지 사기인지
  이진 클래스 분류, 다중 클래스 분류로 나누어진다.

KNN k-최근접 이웃
  새로운 데이터 중 가장 가까운 k개의 이웃을 찾아 해당이웃의 다수결로 레이블을 결정하는 분류방법
  학습 과정 자체가 거의 없다. 데이터 전체를 저장해 두고 예측할 때만 계산하여 분류

  장점 : 단순하다(학습거의 필요없음), 노이즈(멀리 떨어진 값)에 비교적 둔감, 데이터가 많을수록 성능이 괜찮아짐
  단점 : k값을 어떻게 설정해야하는가? 
         만약 k를 1로 설정하면 과적합 위험이 있다.
         k가 너무 크면 세밀한 분류가 어렵고, 자주 바뀔수 있음

         거리계산비용
         예측할때마다 모든 데이터셋의 거리를 계산해야하므로 데이터가 많으면 느려진다.

         스케일 차이에 민감
         범위가 제각각이면 한속성이 거리 계산에 과도한 영향을 줄 수 있음

전처리 (정규화/표준화)의 중요성
 정규화 (min-max nomalization)
  모든 속성을 0~1 범위로 매핑
 표준화 (standardization)
  평균을 빼고 표준편차로 나누어 z-score로 변환
  속성들의 값 범위를 맞춰 줌으로써 거리계산이 왜곡되지 않도록 함.


요약
 데이터 형태(정형/비정형/반정형)의 이해
 
 플렉시빌리티와 효율성의 트레이드오프 개념.
 
 속성(피처)의 타입 구분
 
 명목형 vs. 순서형 vs. 간격척도 vs. 비율척도의 차이
 특히 “0”이 실제로 ‘없음(none)’을 의미하느냐(비율척도), 아니면 단순 기준점이냐(간격척도) 구분이 중요.
 
 KNN의 아이디어와 특성
 학습이 아닌 “메모리 기반” 분류 기법임을 강조
 K 선택과 거리 계산 시 정규화/표준화가 중요한 이유
 노이즈에 대한 KNN의 영향
 노이즈가 분포 바깥에 있기 때문에, K가 적절하다면 노이즈가 예측에 큰 영향을 미치지 않음.
 모델이 아닌 “데이터 자체”를 가지고 예측
 나중에 다른 분류 모델(SVM, Decision Tree, Random Forest 등)과 비교할 때도 KNN의 특성을 이해해야 함.

데이터는 객체(샘플)들의 집합이며, 각 객체는 여러 속성(피처)값으로 표현된다.

속성의 유형(명목형, 순서형, 간격척도, 비율척도)에 따라 분석 및 거리 계산 시 처리 방법이 달라짐.

분류(Classification)
 주어진 데이터의 레이블을 예측하는 문제이며, 이진 또는 다중 분류로 확장 가능.

KNN(K-Nearest Neighbor)
 데이터 기반의 대표적인 분류 기법으로, 모델 학습 과정보다 예측(거리 계산) 때 계산량이 집중됨.

정규화/표준화는 KNN뿐만 아니라 대부분의 거리 기반 알고리즘에서 매우 중요.

노이즈 대응과 K 선택이 KNN 성능에 핵심적인 영향을 미친다.




문제

1. 데이터 형태 관련

[이론형 문제]
“정형(Structured) 데이터, 비정형(Unstructured) 데이터, 반정형(Semi-Structured) 데이터의 차이점과 각각의 장단점을 예를 들어 설명하시오.”

1) 정형(Structured) 데이터  
   - 정의: 사전에 정해진 스키마(행과 열 구조)를 따르는 데이터  
   - 예시: RDBMS의 테이블, CSV 파일  
   - 장점:
       * 검색 및 분석이 용이 (예: SQL 쿼리 사용)
       * 데이터 무결성과 일관성이 유지됨
   - 단점:
       * 스키마 변경이 어려워 유연성이 낮음
       * 복잡한 데이터(텍스트, 이미지 등)는 표현하기 어려움

2) 비정형(Unstructured) 데이터  
   - 정의: 고정된 스키마 없이 자유로운 형태로 존재하는 데이터  
   - 예시: 이미지, 오디오, 동영상, 일반 텍스트 문서  
   - 장점:
       * 다양한 형태의 데이터를 그대로 저장할 수 있어 유연함
       * 창의적 분석(예: 딥러닝 기반 이미지 인식)에 적합
   - 단점:
       * 데이터 내에서 원하는 정보를 추출하는 데 복잡함
       * 저장 공간 및 처리 비용이 많이 듦

3) 반정형(Semi-Structured) 데이터  
   - 정의: 어느 정도 구조를 갖고 있으나 엄격한 스키마가 없는 데이터  
   - 예시: JSON, XML, 로그 파일, IoT 센서 데이터  
   - 장점:
       * 데이터 구조의 유연성과 정형 데이터의 일부 장점을 동시에 제공
       * 다양한 응용 환경에서 활용 가능
   - 단점:
       * 데이터의 구조가 일정하지 않아 분석 시 추가 전처리가 필요할 수 있음

[응용형 문제]
“다음과 같은 형태의 데이터(JSON/이미지/DB테이블 등)가 주어졌을 때, 어떤 형태로 분류할 수 있으며, 왜 그렇게 판단하는지 설명하시오.”

- JSON 데이터:  
  분류: 반정형(Semi-Structured) 데이터  
  이유: JSON은 key-value 쌍으로 데이터를 표현하여 어느 정도 구조를 가지지만, 엄격한 테이블 형식은 아니므로 스키마가 자유롭다.

- 이미지 데이터:  
  분류: 비정형(Unstructured) 데이터  
  이유: 이미지는 픽셀 정보 등 수치 데이터로 변환할 수 있으나, 원본 그대로는 고정된 스키마가 없는 ‘그림’ 형태로 존재한다.

- DB 테이블:  
  분류: 정형(Structured) 데이터  
  이유: DB 테이블은 미리 정의된 스키마(열의 구조)를 갖고 있으며, 모든 행이 동일한 구조를 따르므로 정형 데이터이다.

──────────────────────────────
2. 속성(피처) 타입 구분

[개념형 문제]
“Interval Scale과 Ratio Scale의 차이를 예시와 함께 설명하시오.”

- Interval Scale (간격 척도):  
  특징: 값들 간의 차이는 의미가 있으나, 절대적 0점이 존재하지 않음 (0이 '없음'을 의미하지 않고 단지 기준점임).  
  예시: 섭씨 온도 – 0°C는 온도가 없음을 의미하지 않고, 단순한 기준점이다. (두 배의 의미로 해석할 수 없음)

- Ratio Scale (비율 척도):  
  특징: 절대적 0점이 존재하여 0이 '없음'을 의미하며, 비율 계산이 가능함.  
  예시: 몸무게 – 0kg은 몸무게가 전혀 없음을 의미하며, 60kg은 30kg의 두 배라는 의미로 해석할 수 있다.

──────────────────────────────
[단답형 문제]
“다음 속성(우편번호, Likert 척도, 몸무게, 온도(섭씨))을 각각 명목형/순서형/간격척도/비율척도로 분류하시오.”

- 우편번호: 명목형 (Nominal)  
  (단순 식별자 역할을 하며 수치 연산의 의미가 없음)

- Likert 척도: 순서형 (Ordinal)  
  (순서가 있으나 각 단계 간의 간격이 반드시 동일하지 않음)

- 몸무게: 비율척도 (Ratio Scale)  
  (0kg은 '없음'을 의미하며 비율 계산 가능)

- 온도(섭씨): 간격척도 (Interval Scale)  
  (0°C는 절대적 '없음'을 의미하지 않고, 온도 간 차이는 의미 있으나 비율 계산은 무의미)

──────────────────────────────
[응용형 문제]
“온도를 섭씨에서 켈빈(K)으로 바꿨을 때, 속성 척도(Interval → Ratio)가 어떻게 달라지는지 설명하시오.”

- 섭씨 온도 (Interval Scale):  
  0°C는 온도가 없음을 의미하지 않고 단순 기준점일 뿐이다.

- 켈빈 온도 (Ratio Scale):  
  변환식: K = °C + 273.15  
  켈빈에서 0K는 절대 영도를 의미하며, 온도가 0K이면 실제로 열 운동이 정지한 상태이다.  
  따라서 켈빈 척도에서는 비율 계산이 가능해져, 예를 들어 300K는 150K의 두 배의 열 에너지를 가진다고 해석할 수 있다.

──────────────────────────────
3. K-최근접 이웃(KNN)

[개념형 문제]
“KNN의 원리를 간단히 서술하고, K를 크게 했을 때와 작게 했을 때의 장단점을 비교하시오.”

- KNN 원리:  
  새로운 데이터 포인트가 주어지면, 학습 데이터 집합에서 해당 포인트와의 거리를 계산한 후 가장 가까운 K개의 이웃을 찾는다. 그 이웃들의 레이블에 따라 다수결(또는 가중치 적용)로 최종 분류를 결정한다.

- K가 작을 때 (예: K=1):  
  장점: 국지적 패턴을 세밀하게 반영하여 결정 경계가 세밀하게 형성됨  
  단점: 노이즈나 이상치에 민감하여 과적합 위험이 높음

- K가 클 때 (예: K가 데이터의 큰 비율):  
  장점: 노이즈에 둔감하며 전체적인 분포를 반영하여 안정적임  
  단점: 국지적 특징을 희석시켜 세밀한 분류가 어려워질 수 있음

──────────────────────────────
[서술형 문제]
“KNN 분류 시 Min-Max Normalization(또는 Standardization)이 필요한 이유를 수식과 함께 설명하시오.”

- 이유:  
  KNN은 거리 기반 알고리즘이므로, 각 피처의 값 범위가 다르면 값의 범위가 큰 피처가 거리 계산에 과도하게 영향을 미친다.  
  모든 피처가 동일한 스케일로 반영되어야 공정한 거리 계산이 가능하다.

- Min-Max Normalization:  
  수식: x' = (x - xmin) / (xmax - xmin)  
  => 모든 값을 0과 1 사이로 스케일링하여 상대적 차이를 동일하게 반영

- Standardization (Z-Score Normalization):  
  수식: z = (x - mu) / sigma  
  => 각 피처의 평균(mu)과 표준편차(sigma)를 이용해 데이터가 0을 중심으로 분포하도록 변환

──────────────────────────────
[문제풀이형 문제]
“2차원 평면상에 주어진 데이터(좌표와 레이블)가 있을 때, 새로 들어온 점의 레이블을 K=3, K=5일 때 각각 어떻게 분류하는지 계산 과정을 보이시오.”

예시 (가상의 데이터):
- 학습 데이터:
    * 점 A: (1, 2), 레이블: Red
    * 점 B: (2, 3), 레이블: Red
    * 점 C: (3, 3), 레이블: Blue
    * 점 D: (6, 5), 레이블: Blue
    * 점 E: (7, 8), 레이블: Blue
    * 점 F: (8, 8), 레이블: Red
- 새 점 X: (4, 4)

계산 과정:
1. 각 학습 데이터와 X 사이의 유클리드 거리를 계산  
   예) 점 A와 X의 거리: sqrt[(4-1)^2 + (4-2)^2] = sqrt(9 + 4) = sqrt(13) ≈ 3.61

2. K=3일 때:  
   - 가장 가까운 3개 이웃 (예: 점 B, C, A)  
   - 이웃들의 레이블: Red, Blue, Red  
   - 다수결 결과: Red

3. K=5일 때:  
   - 가장 가까운 5개 이웃 (예: 점 B, C, A, D, F)  
   - 이웃들의 레이블: Red, Blue, Red, Blue, Red  
   - 다수결 결과: Red

(실제 계산 시 모든 점의 거리를 구한 후 오름차순 정렬하여 선택하며, 다수결 또는 가중치 적용 방식으로 최종 레이블을 결정함)

──────────────────────────────
4. 노이즈(Outlier)와 KNN

[서술형 문제]
“노이즈(Outlier)가 존재할 때 KNN 분류가 왜 비교적 안전한지(둔감한지) 설명하시오.”

- 설명:  
  KNN은 예측 시 각 포인트와의 거리를 기준으로 가까운 이웃을 선택하므로, 데이터 전체에서 극단적인 노이즈(이상치)는 대개 멀리 위치한다.  
  따라서 적절한 K값을 사용하면 다수의 정상 데이터에 의해 다수결이 이루어져 소수의 노이즈가 분류 결과에 미치는 영향이 줄어든다.

[개념형 문제]
“KNN에서 노이즈의 영향을 더 줄이기 위해 취할 수 있는 전처리(정규화 외)에 대해 제시하시오.”

- 가능한 방법:  
  * 이상치 제거 (Outlier Removal): 통계적 기법 (예: IQR, Z-Score) 사용  
  * 차원 축소 (Dimensionality Reduction): PCA 등으로 노이즈가 많은 차원 제거  
  * 가중치 부여 (Weighted KNN): 거리에 반비례하는 가중치를 적용  
  * 데이터 스무딩 (Smoothing): 데이터 평활화 기법 적용

──────────────────────────────
5. 종합 응용 문제

[시나리오형 문제]
“어떤 의료 데이터셋에서 환자들의 검사 결과(수치형 속성)와 진단 레이블(양성/음성 바이너리)이 주어졌다. 이때 KNN 알고리즘을 적용하여 분류를 하고자 할 때, 어떤 전처리 과정을 거쳐야 하며, K 선택은 어떻게 할 것인지, 이유를 들어 설명하시오.”

- 전처리 과정:  
  1. 정규화/표준화  
     - 검사 결과의 각 피처 값 범위가 다를 수 있으므로, Min-Max Normalization (x' = (x - xmin) / (xmax - xmin)) 또는 Standardization (z = (x - mu) / sigma)를 통해 스케일을 맞춘다.
  2. 이상치 제거  
     - 기기 오류나 오진 등으로 발생하는 극단적인 값은 Z-Score나 IQR 방법을 사용해 제거하거나 보정한다.
  3. 결측치 처리  
     - 누락된 값이 있다면 평균 대체, KNN imputation 등으로 보완한다.

- K 선택:  
  * 작은 K (예: 1~3): 국지적 패턴을 잘 반영하지만 노이즈에 민감할 수 있음.  
  * 큰 K (예: 10 이상): 안정적이나 국지적 특징이 희석될 위험이 있음.
  * 선택 방법: 교차 검증을 통해 다양한 K값에 대해 성능(분류 정확도 또는 임상적 의미)을 평가하여 최적의 K를 선택한다.
  * 이유: 의료 데이터에서는 진단 오차가 심각할 수 있으므로, 과적합을 피하면서도 충분히 세밀한 국지적 정보를 반영할 수 있는 중간 범위의 K값을 선택하는 것이 중요하다.

──────────────────────────────
[결론]
- 데이터는 정형, 비정형, 반정형으로 구분되며 각각의 특성에 따라 장단점이 있다.
- 속성(피처) 타입은 Interval Scale과 Ratio Scale 등으로 구분되며, 0의 의미와 연산 가능 여부에 따라 구분된다.
- KNN 알고리즘은 새로운 데이터 포인트에 대해 학습 데이터와의 거리를 계산하여 다수결로 분류를 결정하며, K값에 따라 성능이 달라진다.
- 거리 기반 알고리즘의 특성상 정규화/표준화가 필수이며, 노이즈 제거 등 추가 전처리 기법을 적용할 수 있다.
- 실제 응용에서는 데이터 전처리와 적절한 K 선택을 통해 안정적인 분류 모델을 구축하는 것이 중요하다.
